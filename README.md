# 技艺自由主义论文与 AI 写作透明度案例

本仓库公开展示《技艺自由主义：以 20 世纪 60 年代审美革命为枢纽重释技术自由主义》的论文源稿、AI 辅助写作过程记录、版本修订日志与引文核查材料。

它不是一个“AI 帮我写完论文”的案例，而是一个相反的案例：在人文学科论文写作中，AI 应该如何被限制、审计、反复纠错，并最终服从作者的学术判断、文献责任和写作声音。

我希望用这篇论文说明一件事：AI 辅助人文学科写作的关键，不是让 AI 生成更多文本，而是建立一套能让作者持续判断的工作系统。AI 可以检索、比较、质疑、重组、提醒风险，但它不能替代作者提出问题、承担立场、辨认概念张力和对引用负责。

当前 `paper/chapters/` 中的论文文本，已由本地最终修改版 `技术自由主义_v9_20260528.docx` 转换并拆分为 Markdown。为避免二进制文件、Office 元数据和正式学位论文附件带来的公开边界问题，DOCX 文件本体不放入主分支。

## 这个仓库是什么

这个公开包包含四类材料：

- `paper/chapters/`：论文 Markdown 源稿。
- `process/`：写作风格档案、交互记录、修改日志和里程碑记录。
- `references/`：参考文献表、AI 幻觉引用核查清单和分章节引用核对报告。
- `tools/`：导出与排版相关脚本，保留为工作流证据。

这个公开包不是原始 Obsidian 项目目录的完整镜像。原始目录中包含第三方 PDF/EPUB、Word/PPT 导出、系统残留、会议原始转录等内容，这些都不适合直接公开。因此本仓库只保留能支持透明审计的文本、日志和核查材料。

## 配套开源 Skills

这篇论文不是只用了一个聊天窗口完成的。它背后有两个配套开源 skill，用来把 AI 协作从“临时问答”变成可复用、可审计、可迭代的写作基础设施：

- [claude-skill-humanities-writing-companion](https://github.com/tizzy916/claude-skill-humanities-writing-companion)：人文学科写作辅助 skill。它把论文写作拆成论证、结构、段落、句子四层审查，并用写作风格档案约束 AI 不要抹去作者声音。
- [scholar-wendao-skill](https://github.com/tizzy916/scholar-wendao-skill)：学者问道 skill。它用于把一位思想家的核心概念、论证方式和批评姿态蒸馏成 perspective skill，让 AI 可以作为内部审稿者而不是代写者参与论文修改。

在本论文中，前者主要服务于写作过程管理、文风保护、分层审稿和修改日志；后者主要服务于阿伦特、朗西埃、芒福德、斯蒂格勒等思想家的视角蒸馏与魔鬼代言人审稿。

## 为什么人文学科更需要“有边界的 AI”

在人文学科论文中，最危险的 AI 使用方式不是语法润色，而是它会把真正的思想张力抹平。

这篇论文早期 v3.8 版本经历过一次失败的 AI 全文润色。AI 把阿伦特、海德格尔、斯蒂格勒三位思想家的差异整理成漂亮的对仗句式，看起来更“学术”，实际上制造了理论错误。更严重的是，它把作者原本带有第一人称判断、口语节奏和论证跳跃的声音，改写成了光滑的标准学术腔。

这个失败决定了后来的工作原则：

- 不把整篇论文交给 AI “统一润色”。
- 不让 AI 把概念张力处理成圆融综合。
- 不让 AI 生成未经核验的装饰性脚注。
- 不让 AI 把“我”改成“本文”“笔者”等看似客观的表达。
- 不把 AI 的“更像论文”当作真正的学术进步。

人文学科写作的核心不是把话说得更顺，而是保留问题的锋利度、概念之间的摩擦、作者判断的在场，以及文献责任的可追溯性。

## 本论文形成的 AI 写作工作流

### 1. 作者先确定问题，AI 不能替你立论

这篇论文的核心问题是：20 世纪 60 年代先锋艺术、反文化运动和技术想象之间，是否存在一种不同于硅谷技术自由主义的自由传统？

这个问题不是 AI 生成的。AI 可以帮助整理相关文献、提出反例、比较概念，但不能替作者决定论文真正要追问什么。人文学科论文的第一责任，是作者要知道自己为什么写、反对什么、试图推进什么。

可用 AI 做的事：

- 帮你列出一个研究问题的可能学术谱系。
- 帮你找出这个问题可能涉及的概念传统。
- 帮你模拟不同学者会如何反驳你的问题。
- 帮你检查导言是否清楚交代了问题意识。

不该让 AI 做的事：

- 直接生成一个看起来宏大的题目。
- 直接给出“创新点”并包装成论文核心。
- 用“填补空白”“具有重要意义”之类套话替代真实问题。

### 2. 建立知识库，而不是只开一个聊天窗口

这篇论文的工作空间最初被迁移到 Obsidian 中，形成了一个可追溯的项目目录：

- `chapters/` 保存当前源稿。
- `process/修改日志.md` 记录重要版本变化。
- `process/写作风格档案.md` 约束 AI 修改方式。
- `references/` 保存参考文献表、文献索引和引用核查报告。
- `references/citation-audit/` 保存分章节引用核对。

这样做的意义是：AI 每次介入都不是孤立对话，而是进入一个有版本、有证据、有规则的写作系统。

推荐工具：

- Obsidian：管理章节、笔记、文献卡片、修改日志。
- Git：记录公开包版本，留下可审计的提交历史。
- GitHub：公开展示论文、过程记录和核查报告。
- Zotero 或同类文献管理器：管理书目信息和 PDF，但不要把受版权保护的 PDF 上传公开仓库。
- `rg` / ripgrep：快速扫描全文中的术语、引用、AI 痕迹和敏感信息。

### 3. 写一份“写作风格档案”

本仓库中的 `process/写作风格档案.md` 是整个工作流最关键的文件之一。

它不是简单告诉 AI “模仿我的风格”，而是把作者的写作声音变成一套可检查的规则。例如：

- 保留第一人称“我”，不要自动改成“笔者”或“本文”。
- 保留逗号流水句和设问推进，不要强行改成短句。
- 警惕过度对仗、过密破折号、“值得注意的是”等 AI 痕迹。
- 关键术语必须统一，例如 technê、技艺自由主义、做自由、pharmakon。
- 原创概念必须显示学术血缘，不能只靠修辞想象力。

这种档案有两个作用：

- 对 AI：让 AI 每次修改前知道边界。
- 对作者：迫使作者反问自己，“我的声音到底是什么？”

这是人文学科 AI 写作中非常重要的一点：AI 不是只会破坏风格，它也会迫使作者把原本凭感觉运作的写作判断显性化。

### 4. 把 AI 审稿分成层级

这篇论文后来形成了类似代码审查的分层审稿方式：

1. 论证层：这篇论文的核心判断是否成立？
2. 结构层：章节顺序是否服务于论证推进？
3. 段落层：这一段到底在完成什么任务？
4. 句子层：这句话是否准确、有力、符合作者声音？

顺序很重要。不能在论证还没站稳时让 AI 去润色句子。否则它会把一个错误论证修饰得更像论文，风险反而更大。

可复用提示词：

```text
请只做论证层审稿，不要润色句子。指出本文核心判断中最脆弱的三处，并说明为什么。
```

```text
请按“论证层 / 结构层 / 段落层 / 句子层”四级审查这一节。上层问题未解决时，不要提出下层润色建议。
```

```text
请不要改写正文。只标出哪些地方存在概念滑移、未证成跳跃或引用支撑不足。
```

### 5. 把 AI 当作“魔鬼代言人”，不是代写者

这篇论文的多个关键部分使用了 AI 扮演不同思想家的内部审稿者。例如：

- 用 Rancière 视角审查“感性分配”是否被误用。
- 用 Stiegler 视角审查“药理学”是否被简化。
- 用 Mumford 视角审查“民主技术/权威技术”是否被过度乐观化。
- 用 Arendt 视角审查 work、action、judgment 的概念边界。

这不是让 AI “像某个哲学家一样写一段”，而是让它帮助作者发现概念误用、理论投射和论证偷换。

推荐做法：

- 给 AI 一个明确角色：只审稿，不续写。
- 要求它指出反对意见，而不是帮你圆场。
- 要求它引用你给出的材料，不要凭空补文献。
- 审稿意见进入修改日志，而不是直接变成正文。

### 6. 引用核查必须独立于 AI 生成

这个项目最重要的教训之一，是 AI 会制造看起来很真的假引用。

本仓库保留了 `references/20260520_AI幻觉引用核查清单.md`，其中记录了早期发现的幻觉引用，包括虚构期刊文章、主题错配文献、内部页码矛盾等问题。公开包中的论文正文已经做了最小修正，但核查报告被保留下来，因为它恰恰说明透明度不是展示“我没有犯错”，而是展示“错误如何被发现和修正”。

引用核查的基本原则：

- AI 可以帮你列出可疑引用，但不能作为最终来源。
- 每条关键引用必须回到原书、原文、出版商页面、数据库记录或合法 PDF。
- 直接引文必须有页码。
- “某某也讨论过这个问题”这类补强性脚注是高风险区。
- 看起来过于完整的英文引文，反而要警惕。

可用工具：

- Zotero：统一管理文献条目。
- Google Scholar、CNKI、WorldCat、出版社官网、期刊官网：核验文献信息。
- PDF 全文搜索：核对关键词和页码。
- `rg`：扫描正文中的作者年份、页码、可疑引用。
- 引用核查表：按章节记录“准确 / 待优化 / 错误 / 待获取 PDF”。

可复用提示词：

```text
请检查以下引用是否存在 AI 幻觉风险。只根据我提供的参考文献表和原文摘录判断，不要补造新来源。
```

```text
请把这些引用分为：已核实、元数据待修正、内容方向错配、疑似虚构、需要作者回原文确认。
```

### 7. 小步修改，每一步都留痕

这篇论文不是一次性被 AI 改完的，而是经历了许多小版本：

- v3.8：从 Notion 迁移到 Obsidian。
- v4.0：章节拆分和文献系统建设。
- v5.0：整体翻新和引用格式修复。
- v6.0：答辩反馈整合。
- v6.0.17：投稿终版。
- 公开包：删除不适合公开的附件，修正已知幻觉引用，写明公开边界。
- v9.0：以 `技术自由主义_v9_20260528.docx` 为最终修改来源，重新拆分为 GitHub 可读的 Markdown 章节。

每一次重要修改都应该回答三个问题：

- 为什么改？
- 改了哪里？
- 如何验证？

这就是为什么本仓库保留 `process/修改日志.md` 和 `process/v6.0.17_20260510_投稿终版_milestone.md`。AI 写作最怕的是“文本越来越好看，但没人知道它怎么变成这样的”。版本记录就是抵抗这种不透明性的方式。

推荐工具：

- Git：对公开版本做 commit。
- Obsidian：保存过程性日志。
- GitHub：公开最终包。
- Markdown：让论文和过程记录都可读、可 diff、可搜索。

### 8. 公开发布时，公开的是过程，不是全部材料

公开透明不等于把所有东西都丢到 GitHub。

本公开包没有包含：

- 第三方 PDF、EPUB、书籍全文、论文全文附件。
- Word、PPT、旧版导出和模板文件。
- `.DS_Store`、缓存、锁文件、系统残留。
- 原始会议转录。
- 私有云盘目录和下载包。

原因很简单：学术透明度不应该变成版权风险、隐私风险或资料倾倒。真正需要公开的是：

- 论文源稿。
- AI 介入的规则。
- 失败与修正记录。
- 引用核查证据。
- 版本变化说明。
- 公开发布时做过哪些删减和修正。

详见 `PUBLICATION_COMPLIANCE_REPORT.md`。

## 可以使用哪些工具

下面不是唯一工具清单，而是一套人文学科 AI 写作基础设施的组合方式。

### 写作与知识管理

- Obsidian：适合长论文、章节拆分、双链笔记、项目日志。
- Markdown：适合版本管理、Git diff、公开展示。
- Zotero：适合文献条目、PDF 管理、引用格式导出。
- Calibre：适合 EPUB/电子书元数据和格式管理。

### AI 协作

- ChatGPT / Claude / Gemini 等通用大语言模型：适合讨论问题意识、模拟审稿、整理反对意见、做结构建议。
- Codex / Claude Code 等本地或代码型 agent：适合整理文件、批量扫描、维护公开包、生成脚本、用 Git 发布。
- 自定义 GPT / Claude Skill / Codex Skill：适合把“写作规则”固化为可复用工作手册。本项目对应的开源实现是 [claude-skill-humanities-writing-companion](https://github.com/tizzy916/claude-skill-humanities-writing-companion)。
- Perspective skill：适合把某位思想家的概念边界、方法论倾向和批评姿态转化为内部审稿视角。本项目对应的开源实现是 [scholar-wendao-skill](https://github.com/tizzy916/scholar-wendao-skill)。

### 核查与审计

- `rg` / ripgrep：快速扫描术语、引用、AI 痕迹、敏感信息。
- Git：记录每次修改。
- GitHub：公开过程和最终文本。
- 出版社官网、期刊官网、WorldCat、Google Scholar、CNKI：核验文献存在性和元数据。
- PDF 全文搜索与 OCR：核验页码、关键词、直接引文。

### 导出与排版

- Pandoc：Markdown 到 Word/PDF 的常用转换工具。
- python-docx：适合自动化处理 Word 样式、脚注、缩进和模板拼接。
- LibreOffice / Word / WPS：做最终排版检查。
- GitHub Releases：适合发布清理过元数据的 PDF/Word，而不是把二进制文件堆在主仓库。

## 一个可复用的最小工作流

如果要从零开始，用 AI 辅助写一篇人文学科论文，可以按这个顺序搭建：

1. 建一个项目文件夹，至少包括 `chapters/`、`process/`、`references/`。
2. 写一份 `process/写作风格档案.md`，明确作者声音、术语、禁忌表达。
3. 写一份 `process/AI协作规则.md`，说明 AI 可以做什么、不可以做什么。
4. 每次只让 AI 处理一个明确任务：审题、审结构、审段落、查引用风险，不要混在一起。
5. 所有关键修改写入修改日志。
6. 所有引用回到原文核查。
7. 用 Git 保存公开版本。
8. 发布前做版权、隐私、密钥、附件和元数据检查。

## 最重要的原则

AI 辅助人文学科论文写作，最重要的不是“提高效率”，而是让作者拥有更强的判断力。

如果 AI 让你更快地产生文本，却让你更少判断，那它是在削弱写作。  
如果 AI 迫使你更清楚地说明问题、风格、证据、边界和责任，那它才真正进入了学术写作。

这篇论文最终想展示的，不是“AI 可以写论文”，而是：在 AI 越来越会写的时代，作者如何继续练习自己的判断、声音和责任。
